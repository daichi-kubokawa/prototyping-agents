# 利用文脈の抽出フレーム（Context of Use / ISO 9241-11 準拠）

本エージェントの最も重要な出力は、機能一覧ではなく**利用文脈**である。
下流の design-agent は、この文脈を入力変数として配色・レイアウト・アーキテクチャを導出する。
したがって以下の5変数は、**欠落を許さない出力契約**である。

## 抽出すべき5変数

| # | 変数カテゴリ | 抽出すべき具体項目 | 下流で決まるもの |
|---|---|---|---|
| C-1 | **ユーザー（Who）** | 年齢帯・視力/色覚特性・熟練度・認知的余力（睡眠不足、緊急時、マルチタスク下か） | 情報密度・文字サイズ下限・専門用語の可否 |
| C-2 | **タスク（What）** | 1セッションの操作時間・入力量・連続注視時間・失敗の可逆性 | 読解最適化 or 走査最適化・確認ダイアログの要否 |
| C-3 | **装置（With what）** | デバイス種別・画面サイズ・入力方式（親指/両手/スタイラス/手袋/マウス）・把持姿勢 | **操作アンカー位置**・ターゲット寸法・ホバー依存の可否 |
| C-4 | **物理環境（Where / When）** | 環境照度（暗室・屋内照明・屋外直射）・時間帯・騒音・移動の有無 | **輝度極性（Light/Dark）**・コントラスト比・彩度上限 |
| C-5 | **社会的・組織的環境** | 他者への配慮（就寝中の家族、公共空間での覗き見）・ブランド制約・法令/アクセシビリティ要求水準 | 発光量・プライバシー配慮・WCAG 到達目標 |

## 抽出の作法

- 生ヒアリングメモから、利用される**極限状態**（最も過酷な条件下での使用シーン）と、
  潜在ニーズ（言語化されていない認知的負荷）を執拗なまでに抽出する
- ユーザーが「不便だ」と言わなかったとしても、文脈記述の中に制約が埋まっていることがある。
  「〜しながら使う」「〜の時間帯に使う」という何気ない一言が、C-3 / C-4 の本体である
- **抽出できない変数は捏造しない。** `requirements.md` の Open Questions に列挙する

## 特に重大な欠落

**C-3（装置・入力方式）と C-4（物理環境）が空欄のまま下流へ渡すことは、
design-agent の決定モデルを機能不全にする。** この2つは他の変数より優先して確認すること。

C-3 が無ければ操作アンカー位置（D-02）が導出できず、
C-4 が無ければ輝度極性（D-01）が導出できない。両方とも設計の骨格に関わる。

## ヒアリングで C-3 / C-4 を引き出す問い

答えを誘導せず、状況を語ってもらうこと。

- 「その作業をしているとき、体は何をしていますか？」（→ 把持姿勢、片手か両手か）
- 「まわりはどのくらい明るいですか？」（→ 環境照度）
- 「そのとき、まわりに人はいますか？」（→ C-5 社会的環境）
- 「1回の操作は、だいたいどのくらいで終わりますか？」（→ C-2 連続注視時間）
- 「間違えたら、やり直せますか？」（→ C-2 可逆性）

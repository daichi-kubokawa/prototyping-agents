# knowledge/ ―― 方法論

エージェントが**起動時に Read で読み込む**方法論。「どうやって判断するか」を置く。

`../agents/` から分けているのは、単に長いからではない。
**判断基準は「読み込まれなかったとき、何が起きるか」**である。

| | 置き場所 | 例 |
|---|---|---|
| 読み込み失敗が**事故になる** | `../agents/`（本体に残す） | `innerHTML` 禁止、ゼロ・ハードコード原則、成果物リスト |
| 読み込み失敗に**気づける** | ここ（外に出す） | 決定モデルの表、禁則の解説、テンプレート |

XSS の**ルール自体**はエージェント本体にあり、ここには**詳細**（禁止識別子の一覧、CSP、例外条件）だけがある。
knowledge が読まれなくても、禁止は効いたままになる。

## 構成

| ディレクトリ | 中身 |
|---|---|
| `shared/` | 全エージェント共通。ガードレール、フロントエンド防衛規約 |
| `product-agent/` | 利用文脈の抽出フレーム、ヒアリング入力の経路、要件テンプレート |
| `design-agent/` | 決定モデル（輝度極性・Fitts・技術構成）、審美規約、成果物テンプレート |
| `quality-agent/` | 検証ゲート・プロトコル、Bolt 分解と DoD |

> どのファイルをいつ読むかの正は、各エージェントの「Knowledge Loading」節である。
> **ファイルを追加したら、必ずそこにも追記する。** 追記を忘れると、置いただけで読まれない。

## 出典（必須）

各ファイルは冒頭に frontmatter を持つ。**出典のないベストプラクティスを置かない**ためである。

```yaml
---
type: external-standard | mixed | framework-original
sources:
  - "発行元 — 名称 | URL | 適用: どの節に効くか"
original: "外部出典に由来しない部分はどこか"
retrieved_at: 2026-08-09
last_reviewed: 2026-08-09
---
```

| type | 意味 |
|---|---|
| `external-standard` | 全体が公式ガイドライン・標準に由来する |
| `mixed` | 外部出典と独自規約が混在する。`original` でどこが独自かを明記する |
| `framework-original` | **出典がない。** 本フレームワークが構成した規約である |

`framework-original` は「独自だから優れている」という意味ではなく、
**「外部の裏付けがない」という自己申告**である。外部標準と同格に扱わないこと
（`shared/guardrails.md` §7 知識源の優先順位）。

公式ガイドラインは改訂される。`last_reviewed` が古いものを永続的な絶対ルールとして扱わない。
URL は**実在を確認してから**書く。確認していない URL を書くくらいなら、URL 欄を空にすること。

## 変更するとき

- **1ファイル1トピック。** 迷ったら分けるのではなく、まず既存ファイルに追記できないか見る
- 目安は 40〜150行。それを超えたら分割を検討する
- 複数エージェントが参照するものは `shared/` へ。ただし**同じ内容を2箇所に書かない**
- 読み込みは指示ベースなので、静かにサボられることがある。
  重要な規約は、エージェント側の**自己検証チェックリストに項目を足して縛る**
- **新規ファイルには必ず frontmatter を付ける。** 出典が無いなら `framework-original` と書く

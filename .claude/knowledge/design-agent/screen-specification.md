# 画面仕様（`screens.md`）

**「何が必要か」と「どう見えるか」の間にある層。**
`requirements.md` の Must Have から、**画面は何枚で、各画面に何が乗るか**を決める。

これが無いと `figma_make_prompt.md` の Elements 節が書けない。
1画面で自明なプロダクトでは飛ばせるが、複数画面や情報設計が主役のプロダクトでは飛ばせない。

## いつ作るか

`design.md` の **D-00（支配的な設計判断の特定）** で、以下のいずれかに該当したとき。

- 画面が**2枚以上**になる
- **情報設計・認知負荷が支配的**（何を見せるか自体が製品の中身）
- Must Have から画面構成が**一意に決まらない**

該当しなければ作らない。1画面・1入力のプロダクトで作ると、ただの冗長である。

## 導出の順序

```
Must Have（何ができる必要があるか）
   ↓  目的が異なるものを束ねる
画面（1画面 = 1目的）
   ↓  その目的を果たすために必要な情報は何か
表示要素（Information）
   ↓  そこで何ができるか
アクション（Action）と遷移
```

**先に画面を思いつかないこと。** 目的の束から画面が決まる。逆をやると、既視感のある画面構成に寄る。

## テンプレート

```markdown
# screens.md — 画面仕様（DRAFT）

## 画面一覧

| ID | 画面 | 目的（1文） | 由来する Must Have |
|---|---|---|---|
| S01 | 〈…〉 | 〈…〉 | M-1 |
| S02 | 〈…〉 | 〈…〉 | M-2, M-3 |

## S01: 〈画面名〉

### 目的
〈この画面が果たす単一の目的。複数書けるなら画面を分けるべきである〉

### 表示要素（Information）
- 〈要素名〉: 〈何を伝えるか〉
- 〈要素名〉: 〈何を伝えるか〉

### アクション（Action）
- 〈動詞〉: 〈結果／遷移先〉

### 遷移
- → S02（〈条件〉）
```

## 記述規約

- **表示要素は「何を見せるか」であり、「どう見せるか」ではない。**
  「案件名」「現在地ラベル」は可。「16pxのカード」「青いバッジ」は不可（`Guidelines.md` の領域）
- **アクションは動詞で書く。** 「案件の選択 → 詳細画面へ遷移」
- **1画面1目的。** 目的を2つ書きたくなったら、画面を分けるか、どちらかを捨てる
- 各画面は**どの Must Have に由来するか**を明示する。由来を持たない画面はスコープクリープである
- モーダル・ドロワー等も1つの画面として扱ってよい（表示形式は設計側の判断）

## DRAFT 時の分量

**画面3枚までなら 40行以内、それ以上でも 60行以内。**
各画面の表示要素は**主要なものだけ**に絞る。網羅は DEVELOP パスで行う。

## 下流への効き方

`figma_make_prompt.md` の Elements 節は、**この `screens.md` の表示要素に
`Guidelines.md` のトークンを掛け合わせて**書く。

```
screens.md      「案件名」「現在地ラベル」   ← 何を見せるか
Guidelines.md   --font-size-body / --color-accent  ← どう見せるか
       ↓
figma_make_prompt.md  Elements 節
```

どちらかが欠けると、Elements は書けないか、根拠のない具体値で埋まる。

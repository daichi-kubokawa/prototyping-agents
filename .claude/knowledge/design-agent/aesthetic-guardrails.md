# 審美規約 ―― AI slop の徹底排除

生成 AI が無自覚に量産する「Timid（臆病）で凡庸な意匠」は、**明確な品質欠陥**として扱う。
`Guidelines.md` の冒頭に、以下の禁則事項を転記すること。

---

## 0. 優先順位 ―― 可読性は審美に優先する

本規約は「凡庸さの排除」を目的とするが、**可読性とアクセシビリティを犠牲にしてよいという意味ではない。**
両者が衝突した場合、**常に可読性が勝つ。**

| 審美側の主張 | 可読性側の事実 | 採るべき判断 |
|---|---|---|
| 極細の罫線が美しい | 屋外の直射日光下では境界が見えない | **境界を太く・強く** |
| 余白だけで分節したい | 認知余力が低いユーザーは群を認識できない | **明示的な区切りを入れる** |
| アクセントは面積比数％で | 主要導線が見つけられない | **見つかる強さまで上げる** |
| 弱い対比が上品 | 高齢ユーザーが階層を判別できない | **対比を強める** |

**審美規約は「制約が緩い文脈での既定値」である。**
利用文脈が過酷な場合は、その文脈から導出した値が優先する。
**「美しいから細くした」は根拠ではない。**

### 非テキスト要素のコントラスト（見落とされやすい）

**WCAG 1.4.11 は、テキスト以外にも 3:1 を要求する** ―― 罫線・境界・アイコン・グラフィカルオブジェクト。
`Guidelines.md` のカラートークンには、**文字色だけでなく境界線のコントラスト比も実測して併記**すること。

C-1（視力特性）や C-4（環境照度）が厳しい場合、3:1 は下限であって目標ではない。引き上げること。

## 1. 絶対禁止事項（Prohibited Patterns）

| # | 禁止対象 | 禁止する理由 |
|---|---|---|
| P-1 | **意味を持たない装飾グラデーション背景**（紫→青、ピンク→オレンジ等の全面グラデーション、根拠なきグロー、既定値のままのグラスモーフィズム） | 情報の階層を伝えず、面を濁らせるだけの「臆病な装飾」。奥行きは影ではなく**構造と余白**で表現する |
| P-2 | **Inter / Arial / Helvetica（既定値としての）/ Roboto / system-ui の無思考な採用** | 選定ではなく「選定の放棄」。書体はプロダクトの声であり、既定値には声がない |
| P-3 | **角丸・影・境界線の一括適用**（すべてのカードが同じ角丸＋同じドロップシャドウ） | 階層が消え、全要素が等価に見える。強調は「全部を目立たせない」ことでしか生まれない |
| P-4 | **絵文字によるアイコン代替、および多色イラストの安易な配置** | 解像度・文化依存・トーンの破壊 |
| P-5 | **意味なく中央揃えされた長文、および全要素の等間隔配置** | リズムの欠如。視線の起点が消失する |
| P-6 | **彩度の高い色の広面積使用** | 面で語る設計は必ず濁る。色は「点」で使うから効く |

## 2. 要求される設計思想 ―― 「面ではなく、線と点で引き締める」

高品位な IDE テーマ（緻密なシンタックス階層と極小のアクセント）や、
高級ファッション誌（VOGUE 等）の誌面設計（大胆な余白、支配的なタイポグラフィ、極細の罫線、限定された差し色）
に共通する規律を、`Guidelines.md` として構築する。

- **① 面を塗らず、線で分ける**
  領域の分節は塗り分けではなく、罫線・境界・余白の断絶で行う。
  背景は原則として単一の静かな面に留め、面の数を増やさない。
  **ただし線の太さとコントラストは、利用文脈から導出する。**
  屋外・高照度・低視力といった条件下では、**極細の罫線は存在しないのと同じ**である

- **② アクセントは「点」に凝縮する**
  差し色は原則1色（最大2色）に限定し、**画面全体の面積比で数％を超えない**。
  アクセントは「今、注意を向けるべき唯一の場所」を指す機能であり、装飾ではない。
  **ただし「見つけられない」は機能不全である。** 面積を増やさずに、
  コントラストか彩度で発見可能性を確保する

- **③ タイポグラフィが階層を作る**
  階層は色や影ではなく、**ウェイト・サイズ・字間・行間の対比**で作る。
  見出しと本文の対比は臆病であってはならない（弱い対比は最も凡庸な失敗）

- **④ 余白は最も高価な素材である**
  情報密度は C-1 / C-2 から導出し、余白を「埋めるべき空白」ではなく**意図的に確保した資産**として設計する。
  密度の根拠を明記する

- **⑤ 書体選定は「選定理由」とセットでのみ成立する**
  欧文と和文の組み合わせ、ウェイト在庫、判別性（0/O、1/l の区別）、
  利用文脈での可読性（小サイズ・低コントラスト・屋外）を評価軸として明示し、
  **なぜその書体でなければならないかを1段落で論証する。論証できない書体は採用してはならない**

- **⑥ モーションは意味の伝達手段に限る**
  「状態変化の因果を伝える」「注意を誘導する」場合のみ許可。
  所要時間・イージング・段差（stagger）は、C-2 の操作テンポと
  `prefers-reduced-motion` への対応方針とセットで定義する。装飾目的の常時アニメーションは禁止

## 3. 変更要求 → トークン写像（ライブ改修用）

`Guidelines.md` の末尾に、以下の形式の写像表を必ず設けること。
顧客反復（DR-3）では、修正依頼を感覚で処理せず**必ずこの表を経由**してトークンの操作へ変換する。
これにより、3回目以降の修正でもデザインシステムの一貫性が崩れない。

| お客様の言葉 | 変換先 | 操作 |
|---|---|---|
| 「もっと明るく」 | 背景トークン | 明度を1段上げる（**極性は変えない**） |
| 「押しにくい」 | W / D | ターゲット幅を上げるか、距離を短縮する |
| 「ごちゃごちゃする」 | 情報密度・余白 | 密度を1段下げる |
| 「地味」「華やかに」 | アクセント | ❌ 面積を増やさない。彩度かコントラストで解く |

表に無い要求が出た場合は、**その場で写像表に追記する**。
最後の行のように、要望を断らずにデザインシステムの言葉で受け止めて別解を出すことが、
本規約の実践上の要点である。

あなたは**オーケストレータ**です。以下を順に実行してください。

## 1. 準備

1. `prompts/inception_briefing.md` を Read で読み込む（**これが実行手順の正**）
2. `local_env.json` からパラメータをバインドする
3. `MODE` = **DEVELOP**
4. `projects/<PROJECT_SLUG>/` の既存成果物と `review_history.md` をすべて Read で読み込む

引数で対象案件や重点を指定された場合は、それに従う。

$ARGUMENTS

## 2. 実行

`inception_briefing.md` の **DEVELOP パス（DV-1 → DV-2）** を実行する。

- 検証は **blocking**。`FAIL` があれば停止し、担当エージェントへ差し戻す
- 各ゲート完了後は**人間のサインオフを待って停止**する。勝手に次へ進まない
- 検証は `quality-agent` へ委譲する。補完作業は該当する担当エージェントへ委譲する

### DV-1 の実行順序（この順を守ること）

1. `## 顧客反復ログ` の補完（時刻・所要時間・上流への反映を埋める）
2. 反復で確定した仕様変更の**上流反映**（下流ではなく上流を直す）
3. `## 保留指摘（DRAFT）` を1件ずつ判定して消化する
4. 検証ゲート1・2 の実行（`verification-protocol.md` に従う）
5. DR-2 で省いた項目の補完
6. `review_history.md` へ記録し、**停止してサインオフを待つ**

### DV-2

`tasks.md` → `index.html` → 検証ゲート3 → `README.md` → 記録して停止。

## 3. 完了時の出力

DV-1 完了時点で、以下を報告して停止する。

- 検証ゲート1・2 の判定サマリ（`PASS` / `FAIL` / `N/A` の件数）
- **`FAIL` の全件**：検出箇所・内容・差し戻し先・修正対策案
- 上流へ反映した変更の一覧
- 人間に判断を仰ぎたい事項（Open Questions）

ここでは簡潔さより**網羅性**を優先すること。商談中と違い、読む時間はある。

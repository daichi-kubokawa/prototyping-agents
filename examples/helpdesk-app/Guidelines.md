# Guidelines.md — デザイントークン規約（ITERATE）

## 1. 禁則事項

`.claude/knowledge/design-agent/aesthetic-guardrails.md` §1 の全文。`figma_make_prompt.md` の
Constraints 節にも転記済みだが、本書がトークンの一次情報であるため、ここにも全文を掲げる。

**可読性は審美に優先する。** 本節の禁則と C-1〜C-5 の制約が衝突した場合は、常に可読性側を採る
（本案件では C-1/C-4 が未確定＝OQ-1/OQ-2 のため、現時点で衝突は発生していない）。

| # | 禁止対象 | 禁止する理由 |
|---|---|---|
| P-1 | 意味を持たない装飾グラデーション背景（紫→青、ピンク→オレンジ等の全面グラデーション、根拠なきグロー、既定値のままのグラスモーフィズム） | 情報の階層を伝えず、面を濁らせるだけの「臆病な装飾」。奥行きは影ではなく構造と余白で表現する |
| P-2 | Inter / Arial / Helvetica（既定値としての）/ Roboto / system-ui の無思考な採用 | 選定ではなく「選定の放棄」。書体はプロダクトの声であり、既定値には声がない |
| P-3 | 角丸・影・境界線の一括適用（すべてのカードが同じ角丸＋同じドロップシャドウ） | 階層が消え、全要素が等価に見える。強調は「全部を目立たせない」ことでしか生まれない |
| P-4 | 絵文字によるアイコン代替、および多色イラストの安易な配置 | 解像度・文化依存・トーンの破壊 |
| P-5 | 意味なく中央揃えされた長文、および全要素の等間隔配置 | リズムの欠如。視線の起点が消失する |
| P-6 | 彩度の高い色の広面積使用 | 面で語る設計は必ず濁る。色は「点」で使うから効く |

## 2. カラートークン

D-01（輝度極性: Light、非支配的だが既定採用）に基づく。オフィス通常照度を仮定し、
純白の大面積による眩しさを避けるためオフホワイト背景を採用する。

| トークン | 値 | 対比相手 | 比率 | 要求 |
|---|---|---|---|---|
| `--bg` | `#F7F7F5` | — | — | — |
| `--fg` | `#1B1B1D` | `--bg` | 16.03:1 | 4.5:1 |
| `--fg-secondary` | `#54545A` | `--bg` | 7.01:1 | 4.5:1 |
| `--border` | `#6E6E72` | `--bg` | 4.73:1 | 3.0:1 |
| `--accent` | `#B42318` | `--bg` | 6.13:1 | 3.0:1 |
| `--accent-fg` | `#FFFFFF` | `--accent` | 6.57:1 | 4.5:1 |

`--accent`（緊急度バッジのみ。requirements.md M-12 由来。「優先度」ではなく「緊急度」の表記へ統一する
―― quality-agent 検証ゲート2 G2-8 対応）は面積比で画面全体の数%以内に限定する（P-6）。

## 3. タイポグラフィ

書体: **IBM Plex Sans JP**（和文欧文統一ファミリー）。0/O・1/l の判別性が高く、
対応記録中の型番・日時表記を誤読なく識別できるため採用する（選定理由）。

| トークン | サイズ | 用途 |
|---|---|---|
| `--font-size-heading` | 20px | 画面見出し・第1階層要素 |
| `--font-size-body` | 15px | 本文・テーブルセル |
| `--font-size-caption` | 13px | メタ情報（日時・チャネル） |

## 4. スペーシング

近接（群内 / 群間、2倍以上を維持）:

| トークン | 値 | 用途 |
|---|---|---|
| `--space-inner` | 8px | 群内（ラベルと値、アイコンとテキスト） |
| `--space-outer` | 20px | 群間（テーブル行グループ、セクション間） |

## 5. コンポーネント規約

| トークン | 寸法 | 用途 |
|---|---|---|
| `--target-primary` | 高さ 40px ／ 最小幅 160px | 主要導線（「類似履歴を検索」等7文字級ラベル） |
| `--target-choice` | 高さ 36px ／ 最小幅 96px | 状況選択肢（「対応済み」4文字＋余白） |

いずれも横並び配置時は `flex-shrink: 0` を必須指定する（縮み止め）。

## 6. モーション規約

`aesthetic-guardrails.md` §2⑥「モーションは意味の伝達手段に限る」に従う。C-1「複数の問い合わせを並行して
処理しながら…緊急対応が通常業務に割り込む状況下で判断を行う」ため認知的余力が逼迫しており（design.md D-00）、
装飾目的の常時アニメーションは認知負荷を上げるだけであり不採用とする。

| トークン | 値 | 用途・意味 |
|---|---|---|
| `--motion-duration-state` | 150ms | 対応状況（T-11〜T-13）の変更時、変化前後の値をクロスフェードし「何が変わったか」の因果を伝える。長すぎると並行処理中の注視の妨げになるため短く保つ（C-2） |
| `--motion-duration-panel` | 200ms | 引き継ぎ先・引き継ぎメモの入力フォーム（段階的開示）が開閉する際、唐突な出現による視線の迷子を防ぐ |
| `--motion-easing` | ease-out | 状態変化は「素早く始まり穏やかに収まる」ことで、変化の終着点を予測しやすくする |

- 一覧テーブルの行の出現・並べ替え、緊急度バッジそのものには、意味を持たないアニメーションを付けない（P-1 の趣旨）
- `prefers-reduced-motion: reduce` が指定された環境では、上記2トークンの `duration` を `0ms` とし、
  状態変化は瞬時に切り替える（因果の伝達はテキスト・色・文字ラベルで担保されており、動きに依存しない）

## 7. 変更要求 → トークン写像表

| お客様の言葉 | 変換先 | 操作 |
|---|---|---|
| 「もっと明るく」 | `--bg` | 明度を1段上げる（極性は変えない） |
| 「押しにくい」 | `--target-primary` / `--target-choice` | 幅を上げるか距離を短縮する |
| 「ごちゃごちゃする」 | `--space-inner` / `--space-outer` | 密度を1段下げる |
| 「地味」「華やかに」 | `--accent` | 面積は増やさず、彩度かコントラストで解く |
| 「緊急が見つけにくい」 | `--accent` | コントラストを引き上げる（面積は据え置き） |

## 8. 禁止識別子リスト

`.claude/knowledge/shared/frontend-security.md` §2 準拠。`figma_make_prompt.md` の Constraints 節にも
転記済みだが、実装者が本書だけを見ても規約を満たせるよう、ここにも全文を掲げる。

- **DOM バインドの絶対規約**: `innerHTML` / `outerHTML` / `insertAdjacentHTML` / `document.write` による
  ユーザー入力・外部応答・AI 生成テキストの展開を全面的に禁止する（例外なき禁止）
- すべての動的要素は `document.createElement()` で生成し、テキストの流し込みは `.textContent`
  （または `.innerText`）経由に限定する
- 属性値の設定は `setAttribute()` を用い、`href` / `src` / `formaction` など URL を解釈する属性には、
  `javascript:` および `data:` スキームを拒否する検証を必須とする
- イベントハンドラは `addEventListener` でのみ束縛する。インライン `onclick=`、`eval()`、`new Function()`、
  文字列引数の `setTimeout` を禁止する
- テンプレートリテラルによる HTML 文字列組み立ては、たとえ静的に見えても禁止する
- フレームワークのエスケープ回避 API（`dangerouslySetInnerHTML`、`v-html`、`@html` 等）も同様に全面禁止する

**grep で検知する禁止識別子（`grep -rn -f <リスト> <対象ファイル>` で 0 件を確認する）**

```
innerHTML
outerHTML
insertAdjacentHTML
document.write
eval(
new Function(
dangerouslySetInnerHTML
v-html
```

**秘匿情報の保持（M-18 関連）**: 保持先（メモリ／セッション／永続）は `requirements.md` §5.1 の
ライフサイクル要件（「必要最小限の範囲・期間に限定する」、OQ-4 未解消）に一字一句従う。
design.md §6 と矛盾する永続化・キャッシュを示唆する実装をしないこと。

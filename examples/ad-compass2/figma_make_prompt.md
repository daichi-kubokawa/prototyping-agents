## Task

展示会・空間デザイン制作会社向けの業務支援ツール「AD-Compass」のプロトタイプ画面を作成する。対象は AD（アートディレクター）不在案件を兼務するグラフィックデザイナー（Lv3、AD 昇格移行期）で、見積・納期設定・確認先選定という単発かつ低可逆な判断を、フルリモートの PC 作業（着座・マウス操作）の中で一人で抱え込まずに下せるよう支援する画面を設計する。

## Context

- 利用者はデザイナー Lv3。AD 業務の判断基準を未習得で、繊細な気質から相手の感情を過剰に汲み取り、相談自体を躊躇しやすい。
- 相談は Teams 上で行われ、営業・コーディネーター2名・AD・センターマネージャーへ可視/非対称になりうる組織構造。率直な指摘を避ける文化があり心理的安全性への配慮が必要。
- 判断（見積妥当性・納期設定・確認相手の選定）は案件工程中に単発かつ即応的に発生し、クライアント提示後の見積・納期は事実上やり直せない（低可逆）。
- 入力方式はマウス。着座・両手のキーボード・マウス操作が中心で、移動中・片手作業の想定はない。

## Elements

1. **判断基準参照パネル（主要導線・常時表示）**
   見積・納期・工程設計の各局面で「何に照らして判断したか」を本人が言語化できるチェックリスト/参照カードを、サイドパネルとして画面内に常駐させる。呼び出し操作（モーダル起動等）を挟まない。
2. **相談先ナビゲーター（主要導線・常時表示）**
   案件工程ごとに「誰に・何を・どの範囲まで」相談すべきかを明示するリスト。相手の感情状態を憶測させる文言（多忙さの推測を促す表現等）を含めない、事実ベースの中立な文面とする。
3. **相談テンプレート起票**
   相談先ナビゲーターから連続して、感情を汲み取らずに相談を開始できる定型テンプレート（要件・締切・確認したい論点のみを構造化）を起票する導線。
4. **見積・納期確定アクション（破壊的操作）**
   主要導線から意図的に距離を離した独立エリアに配置。確定前に確認ステップ（サマリ再表示＋明示的な同意操作）を挟む。
5. **案件完了後フィードバック画面**
   AD 業務の各工程（見積・納期・確認・進行）に対する具体的・改善志向のコメントを表示する。「良かった」で終わる曖昧な賞賛ではなく、次工程で使える具体的な指摘であることが検証条件。

## Behavior

- 判断基準参照パネルと相談先ナビゲーターは、他の作業（見積入力・工程確認）と同時に視認できる状態を初期状態とする。
- 見積・納期確定アクションは、クリック後ただちに確定せず、確認ステップを経てから確定する（誤操作防止）。
- 状態: 初期／入力中／確認待ち／確定済み／相談送信済み／フィードバック受領済み の各状態を UI 上で判別可能にする。
- モーションは状態変化の因果を伝える場合のみ許可し、装飾目的の常時アニメーションは禁止する。

## Constraints — 必ず遵守すること

### デザイントークン（Guidelines.md より）
- `color-bg`: `#FAFAF8`（Light、純白ではなくオフホワイト）
- `color-fg-primary`: `#1C1C1A`（本文、対背景コントラスト 16.33:1）
- `color-fg-secondary`: `#6B6B66`（補助テキスト、5.13:1）
- `color-border`: `#8F8F86`（罫線、3.12:1。塗り分けではなく線で領域を分節する）
- `color-accent`: `#4C5FBF`（単一アクセント。警戒色を避けた低彩度の青。画面面積の数％以内に限定）
- 書体: 欧文/数字 `IBM Plex Sans`、和文 `Zen Kaku Gothic New`
- サイズ: 見出し `20px` ／本文 `15px` ／補助 `13px`
- スペーシング: `4px` 基準（4/8/16/24/32/48）
- ターゲット寸法: 主要導線（判断基準参照・相談先ナビゲーション）はクリック領域高さ `40px` 以上・行/カード全体。破壊的操作（確定ボタン）は `32px` 程度に絞り、主要導線から独立した余白を確保する。

### 禁則事項（AI slop の排除、P-1〜P-6）
| # | 禁止対象 |
|---|---|
| P-1 | 意味を持たない装飾グラデーション背景、根拠なきグロー、既定値のグラスモーフィズム |
| P-2 | Inter / Arial / Helvetica（既定値としての）/ Roboto / system-ui の無思考な採用 |
| P-3 | 角丸・影・境界線の一括適用（全カードが同じ装飾） |
| P-4 | 絵文字によるアイコン代替、多色イラストの安易な配置 |
| P-5 | 意味なく中央揃えされた長文、全要素の等間隔配置 |
| P-6 | 彩度の高い色の広面積使用 |

背景は単一の静かな面に留め、領域分節は塗り分けではなく罫線・余白で行うこと。アクセントは `color-accent` の1色のみとし、面積比で数％を超えないこと。

### DOM バインド規約（実装時、例外なき禁止）
- `innerHTML` / `outerHTML` / `insertAdjacentHTML` / `document.write` によるテキスト展開を全面禁止する。
- すべての動的要素は `document.createElement()` で生成し、テキストは `.textContent` 経由でのみバインドする。
- 属性値は `setAttribute()` を用い、URL を解釈する属性（`href` / `src` / `formaction`）には `javascript:` / `data:` スキームを拒否する検証を必須とする。
- イベントハンドラは `addEventListener` でのみ束縛する。`onclick=` 等のインライン属性、`eval()`、`new Function()`、文字列引数の `setTimeout` を禁止する。
- テンプレートリテラルによる HTML 文字列組み立てを禁止する（静的に見えても禁止）。
- フレームワークのエスケープ回避 API（`dangerouslySetInnerHTML`、`v-html` 等）を禁止する。
